hypothesis here is scored only on data produced after run 3's `started_at` in
`data/paper_run_manifest.json`. Each one comes from something already seen in run 1/2
or older data (cited per hypothesis), which is exactly why none of that data may be
used to score it.

## H-L — the live IC candidates are real

*Origin:* the exploratory 40-day scan on run 1+2 (`2026-10-09` session, 12 fields × 3
horizons). Two fields stood out, and with 36 tests some stars were expected by chance.

On run-3 **futures** cycles, Spearman IC against the forward 24h BTC return, with a
90% block bootstrap (24h blocks, 2,000 resamples):

- **H-L1 basis_pct:** PASS if IC > 0 **and** the CI lies entirely above 0.
- **H-L2 ls_ratio:** PASS if IC > 0 **and** the CI lies entirely above 0.
- FAIL if the CI lies entirely below 0. INCONCLUSIVE otherwise.
- Power guard: fewer than 500 hourly observations with both the field and the forward
  return present → INCONCLUSIVE.
- Placeholder rows (fetch failures: funding 0, L/S 1.0, basis 0) are dropped per field,
  exactly as `history.get_market_history` drops them.

## H-V — relative bands score better than absolute ones

*Origin:* run 2's dead-condition count (funding, L/S and basis scored 0 of 92 futures
cycles) and the live IC scan.

**Primary, H-V1 (per cycle; it has the power the trade count never will).** For each
run-3 futures cycle, take net score = `buy_score − sell_score` for `base`,
`rel_engine_dir` and `rel_ic_dir` from `cycle_log.variants`. Compute each net score's
Spearman IC against the forward 24h return, and the paired difference `IC(variant) −
IC(base)` under the same block bootstrap (resample cycles jointly).

- A variant **PASSES** if `IC(variant) − IC(base) > 0` **and** its 90% CI lies entirely
  above 0.
- **FAILS** if the CI lies entirely below 0. **INCONCLUSIVE** otherwise.
- Same 500-observation power guard as H-L.
- Two variants are tested. Both are reported. If both pass, the one with the larger
  difference is the candidate, and the comparison between the two is descriptive.

**Secondary, H-V2 (books).** `scripts/variant_books.py` on run 3's database, futures
and spot separately. Per-trade mean of each variant book against the `base` book.
Descriptive unless a book resolves ≥ 30 trades, in which case the same
"mean higher and 90% CI on the difference above 0" rule applies. **H-V2 can corroborate
H-V1. It cannot overturn it.**

**Fidelity check (must hold, or H-V2 is discarded):** the replayed `base` book must
open within ±1 bar of every position the live bot actually opened in the same mode
over the same span, allowing for differences the replay cannot see (pyramiding,
macro-close, breaker), which are listed individually.

**What a PASS licenses:** promoting that variant's bias rule to the main engine **in
run 4**, and nothing more. Not the weights, not the threshold.

## H-B — the engine beats random entry on BTC

*Origin:* `2026-10-09-loss-diagnosis.md`. BTC beat random by +0.38pp in both
`2026-09-24-entry` windows and by +1.0pp in the aged-anchor sequence. BTC was picked
after seeing nine symbols, and the system was designed on BTC.

**Data:** BTC/USDT 4h, **2026-08-30 → run 3's end**. Nakhoda's cache stops at
2026-08-30, so not one of these candles has been read by any experiment here.
Fetched from the exchange with ≥ 250 candles of warmup before the window. The CSV is
saved in the run folder with its SHA-256 recorded in the results.

**Protocol:** `scripts/entry_ic.py`'s independent-entry method, unchanged: `spotsignal`
arm against a count-matched random arm (20 seeds), same exits, same costs, fixed
`SPOT_THRESHOLD`.

- **PASS** if `spotsignal.mean − random.mean > 0` **and** spotsignal's 90% bootstrap
  interval excludes `random.mean`.
- **FAIL** if `spotsignal.mean ≤ random.mean`.
- **Power guard:** `spotsignal.n < 30` → INCONCLUSIVE. At ~1.5 engine BUYs a week this
  window may not reach 30 by day 30, and if so the verdict waits until it does, up to
  run 3's end. It is not scored early.

**What a PASS licenses:** treating BTC as the system's working universe in writing.
Live already trades BTC only, so no code changes. It does **not** license trading
anything else, and it is not evidence of profit after costs. That is a separate
question for the books.
