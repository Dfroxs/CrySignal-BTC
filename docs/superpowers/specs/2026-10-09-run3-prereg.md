## H-L — the live IC candidates are real

*Origin:* the exploratory 40-day scan on run 1+2 (`2026-10-09` session, 12 fields × 3
horizons). Two fields stood out, and with 36 tests some stars were expected by chance.

On run-3 **futures** cycles, Spearman IC against the forward 24h BTC return, with a
90% block bootstrap (24h blocks, 2,000 resamples):

- **H-L1 basis_pct:** PASS if IC > 0 **and** the CI lies entirely above 0.
- **H-L2 ls_ratio:** PASS if IC > 0 **and** the CI lies entirely above 0.
- FAIL if the CI lies entirely below 0. INCONCLUSIVE otherwise.
- Power guard: fewer than 500 hourly observations with both the field and the forward
  return present → INCONCLUSIVE.
- Placeholder rows (fetch failures: funding 0, L/S 1.0, basis 0) are dropped per field,
  exactly as `history.get_market_history` drops them.

## H-V — relative bands score better than absolute ones

*Origin:* run 2's dead-condition count (funding, L/S and basis scored 0 of 92 futures
cycles) and the live IC scan.

**Primary, H-V1 (per cycle; it has the power the trade count never will).** For each
run-3 futures cycle, take net score = `buy_score − sell_score` for `base`,
`rel_engine_dir` and `rel_ic_dir` from `cycle_log.variants`. Compute each net score's
Spearman IC against the forward 24h return, and the paired difference `IC(variant) −
IC(base)` under the same block bootstrap (resample cycles jointly).

- A variant **PASSES** if `IC(variant) − IC(base) > 0` **and** its 90% CI lies entirely
  above 0.
- **FAILS** if the CI lies entirely below 0. **INCONCLUSIVE** otherwise.
- Same 500-observation power guard as H-L.
- Two variants are tested. Both are reported. If both pass, the one with the larger
  difference is the candidate, and the comparison between the two is descriptive.

**Secondary, H-V2 (books).** `scripts/variant_books.py` on run 3's database, futures
and spot separately. Per-trade mean of each variant book against the `base` book.
Descriptive unless a book resolves ≥ 30 trades, in which case the same
"mean higher and 90% CI on the difference above 0" rule applies. **H-V2 can corroborate
H-V1. It cannot overturn it.**

**Fidelity check (must hold, or H-V2 is discarded):** the replayed `base` book must
open within ±1 bar of every position the live bot actually opened in the same mode
over the same span, allowing for differences the replay cannot see (pyramiding,
macro-close, breaker), which are listed individually.

**What a PASS licenses:** promoting that variant's bias rule to the main engine **in
run 4**, and nothing more. Not the weights, not the threshold.

## H-B — the engine beats random entry on BTC

*Origin:* `2026-10-09-loss-diagnosis.md`. BTC beat random by +0.38pp in both
`2026-09-24-entry` windows and by +1.0pp in the aged-anchor sequence. BTC was picked
after seeing nine symbols, and the system was designed on BTC.

**Data:** BTC/USDT 4h, **2026-08-30 → run 3's end**. Nakhoda's cache stops at
2026-08-30, so not one of these candles has been read by any experiment here.
Fetched from the exchange with ≥ 250 candles of warmup before the window. The CSV is
saved in the run folder with its SHA-256 recorded in the results.

**Protocol:** `scripts/entry_ic.py`'s independent-entry method, unchanged: `spotsignal`
arm against a count-matched random arm (20 seeds), same exits, same costs, fixed
`SPOT_THRESHOLD`.

- **PASS** if `spotsignal.mean − random.mean > 0` **and** spotsignal's 90% bootstrap
  interval excludes `random.mean`.
- **FAIL** if `spotsignal.mean ≤ random.mean`.
- **Power guard:** `spotsignal.n < 30` → INCONCLUSIVE. At ~1.5 engine BUYs a week this
  window may not reach 30 by day 30, and if so the verdict waits until it does, up to
  run 3's end. It is not scored early.

**What a PASS licenses:** treating BTC as the system's working universe in writing.
Live already trades BTC only, so no code changes. It does **not** license trading
anything else, and it is not evidence of profit after costs. That is a separate
question for the books.

## H-S: do the agents' AGREE signals beat their DISAGREE signals?

*Origin:* the owner's proposal to put an LLM over the bot's decisions. It was rejected as
a live gate (an LLM cannot be honestly backtested on candles inside its training data)
and built instead as logging only. Run 3's candles post-date both models' training
data, so this is the first fair test of the idea.

**Agents:** Claude (`claude-opus-5-5`) and DeepSeek (`deepseek-v4-pro`), each judging
every non-HOLD, non-cached signal from numbers only (`agents/shadow.build_context`),
stored in `shadow_opinions`.

**Statistic:** `scripts/shadow_eval.py`. Per opinion without an error, take the forward
24h return in the signal's direction, from its entry price to the futures cycle price
24h later. Per provider: `mean(AGREE) − mean(DISAGREE)`, with a 90% bootstrap interval
(5,000 resamples).

- **PASS** if the difference > 0 **and** the CI lies entirely above 0.
- **FAIL** if the difference ≤ 0. **INCONCLUSIVE** otherwise.
- **Power guard:** fewer than 20 opinions in either group → INCONCLUSIVE. Each provider
  is scored separately.
- Claude against DeepSeek, head to head, is **descriptive only**.

**What a PASS licenses:** pre-registering, for run 4, a test of that provider as a
*veto gate* on the live bot. It does **not** license wiring the agent into trading
directly. A shadow pass shows that the agent separates good signals from bad ones. It
does not show that vetoing with it beats the gates already in place.

**Discard:** if a provider's errors exceed 20% of its calls, that provider is discarded
for run 3 (the agent was down, not wrong).

# Amendment, 2026-10-09 ~06:00 UTC: H-S measures the trade the bot would run

Written in run 3's first hour, before any H-S figure was computed. Nothing else in this
document changes.

**Why.** H-S asked the agents about, and scored them on, a fixed **24h** return. That
matches neither mode. Both close trades through stops, targets and trailing stops within
a **72h** cap. Futures stops and targets are widened ×2 at open, so the agents were shown
levels the bot never uses. Spot is long-only, and the costs differ per mode
(spot ~0.30%, futures ~0.18%). The owner flagged the mismatch.

**Changed.**

- **The question.** Each agent now sees an `exit_rules` block for the signal's mode
  (`agents/shadow.exit_terms`), with the levels the bot would actually open with, and is
  asked whether *that managed trade* closes at a net profit.
- **The primary statistic.** Per opinion, the net P&L of that trade replayed through
  `backtest._simulate_forward` with the stored stop/target levels, entered on the bar the
  bot scored (`scripts/shadow_eval.trade_outcomes`). Per provider: `mean(AGREE) −
  mean(DISAGREE)`, with a 90% bootstrap CI. The PASS / FAIL / INCONCLUSIVE rules and the
  20-per-group power guard are unchanged. Trades still open at the data's end are
  excluded.
- **The signed 24h return** is now descriptive only.

**Which opinions count.** Only opinions recorded **after the deploy of this change**
(the timestamp is noted in PAPER_RUN.md). Any opinion recorded earlier in run 3 was
asked the old question and is excluded.

## H-X: does following the agents' CLOSE/HOLD advice beat the bot's own exits?

*Origin:* the owner asked why the agents were not proposed for open AND close decisions.
The entry shadow (H-S) covers opens. This covers closes, logged only.

**What is asked:** once per full cycle, for each open position, each provider answers
CLOSE (now, at the cycle price) or HOLD (let the bot's exits run), from numbers only
(`agents/exit_shadow.build_exit_context`).

**Statistic:** `scripts/exit_shadow_eval.py`, over positions that have closed. Per
opinion:

- **value of a CLOSE** = (P&L if closed at the opinion's price) − (the position's final P&L)
- **value of a HOLD** = (the position's final P&L) − (P&L if closed at the opinion's price)

Both P&Ls are computed by the bot's `_calc_pnl`. Per provider, take the mean value,
with a 90% **cluster** bootstrap over positions (5,000 resamples), because hourly
opinions on one position are not independent.

- **PASS** if the mean > 0 **and** the CI lies entirely above 0.
- **FAIL** if the mean ≤ 0. **INCONCLUSIVE** otherwise.
- **Power guard:** fewer than 8 closed positions or fewer than 30 opinions →
  INCONCLUSIVE.
- **Honest expectation:** run 3 may not open 8 positions in 30 days. If so, H-X stays
  INCONCLUSIVE and carries into run 4 with the same rules. It is not scored on less.

**What a PASS licenses:** pre-registering, for run 4, that provider as an exit *advisor*
whose CLOSE is acted on. It does not license acting on it directly.

**Discard:** a provider whose errors exceed 20% of its calls is discarded.
**Counts from:** the deploy of this change (timestamp noted in PAPER_RUN.md).
